# Motion

Motion explains a change: it gives feedback, keeps track of where things came from, and makes the interface feel
responsive. It should feel calm, refined, and quick. Never bouncy, and never decoration for its own sake. When in
doubt, choose the subtler option. The full principles live in `MOTION.md`, and how to apply them per component is in
[Guidelines → Motion](?path=/docs/guidelines-motion--docs).

Every value on this page comes from `src/lib/motion/`, which the library exports:

```tsx
import { motion } from "motion/react";
import { liftPattern, revealVariants, motionDuration } from "@jcaunedo/intercept-ucl";

<motion.div {...liftPattern}>…</motion.div>;
```

## Rules of thumb

- **Use the presets.** Reach for a pattern or variant below before writing an animation, and never put raw durations,
  curves, or distances in a component. If something new is needed, add it as a token in `src/lib/motion/`.
- **Exits are shorter than entrances.** One documented exception: `expandVariants` closes its height on the same curve
  as the open, because an ease-in collapse reads as a hard stop.
- **Respect reduced motion.** Components read `useMotionPreference()` and pass their transitions through its
  `resolve`, which swaps in a near-instant one. Movement goes away; the state change stays visible.
- **Animate `opacity` and `transform`.** Prefer Motion's `layout` for size and position changes over animating
  `height`, `top`, or `margin` by hand.
